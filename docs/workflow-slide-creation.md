# スライド作成ワークフロー

このドキュメントは、AI エージェントが「スライド作成して」とリクエストされた時に従うワークフローです。

## トリガーとなるユーザーリクエスト

以下のようなリクエストを受けた場合、このワークフローを実行してください：

- 「スライド作成して」
- 「新しいスライドを作りたい」
- 「プレゼン作って」
- 「発表資料を作成して」

## ワークフロー

### ステップ 1: ファイル名とテーマを質問 → スライドファイル作成

```
スライドを作成しますね！

以下の2点を教えてください：

1. ファイル名（拡張子なし）
   例：project-report, team-meeting, product-launch

2. テーマ（番号または名前）
   a. gradient - 紫のグラデーション（華やかなデザイン）
   b. default - シンプルな標準テーマ（ビジネス向け）
   c. darkmode - ダークモード（技術系向け）
```

**ユーザーの回答を待つ**

**回答を受け取ったら、すぐにスライドファイルを作成：**

```bash
# AIエージェント向け（非対話型）
make new NAME=[ファイル名] THEME=[テーマ]

# 例
make new NAME=project-report THEME=gradient
```

作成完了を報告してから次のステップへ：

```
✅ スライドファイルを作成しました: workspace/slides/[ファイル名].md

続いて、スライドの内容について教えてください。
```

### ステップ 2: スライド内容を質問

```
スライドの内容を教えてください。

例えば：
- 「タイトル、目次、本編3枚、まとめ」
- 「プロジェクト進捗報告：背景、現状、課題、今後の予定」
- 「製品紹介：特徴、メリット、価格、お問い合わせ」

どんな内容にしますか？
```

**ユーザーの回答を待つ**

### ステップ 3: 画像について確認

```
スライドに画像を含めますか？

- Yes → 画像のURLまたはファイルを教えてください
- No → スキップして次に進みます

※ 注意: AI画像生成やストック画像の自動取得は行いません。
  お持ちの画像やURLを指定してください。
```

**画像が必要な場合：**

1. ユーザーから画像 URL or ファイルパスを受け取る
2. `workspace/img/` にダウンロード/コピー
3. 「この画像でいいですか？」と確認
4. OK なら次のステップへ

**画像不要の場合：** 次のステップへ進む

### ステップ 4: スライド内容の編集

ステップ 1 で作成した `workspace/slides/[ファイル名].md` を開き、ユーザーが指定した内容に基づいて Markdown を編集します。

**編集のポイント：**

- タイトルスライドには `<!-- _class: title -->` を使用
- スライドは `---` で区切る
- 画像は `![width:500px](../img/image.png)` 形式
- 箇条書き、表、コードブロックなど適切に活用

**画像を含める場合：**

```markdown
<!-- 出典: https://example.com/page -->

![説明文](../img/downloaded-image.png)
```

**Markdown 構文の参考：** [使い方ガイド](usage.md)

### ステップ 5: プレビュー案内

スライドファイルの編集が完了したら、プレビュー方法を案内します。
**自動でビルドやプレビューは実行しません。**

```
スライドの編集が完了しました！

プレビューで確認するには以下のコマンドを実行してください：

make preview

ファイル名「[ファイル名]」を入力すると、ブラウザでプレビューが開きます。
編集すると自動で更新されます。終了は Ctrl+C。

プレビューの実行をお手伝いしましょうか？
```

**ユーザーの回答を待つ**

- 「はい」「お願い」→ 非対話型コマンドでプレビューを実行：
  ```bash
  make preview FILE=workspace/slides/[ファイル名].md
  ```
- 「いいえ」「自分でやる」→ 次のステップへ

### ステップ 6: 修正フェーズ

プレビュー後、修正が必要か確認します。修正がなくなるまでループします。

```
修正箇所はありますか？

あれば内容を教えてください。なければ「なし」と答えてください。
```

**ユーザーの回答を待つ**

- 修正あり → Markdown を編集 → 再度「修正箇所はありますか？」
- 修正なし（「なし」「OK」「完成」等）→ 次のステップへ

### ステップ 7: ビルド確認

修正が完了したら、ビルドするか確認します。

```
ビルドしますか？

1. はい、全形式（PDF/PPTX/HTML）
2. PDFのみ
3. PowerPointのみ
4. HTMLのみ
5. いいえ、ビルドしない
```

**ユーザーの回答を待つ**

| 回答       | アクション                                             |
| ---------- | ------------------------------------------------------ |
| 1 / 全形式 | `make build-one FILE=workspace/slides/[ファイル名].md` |
| 2 / PDF    | `make pdf-one FILE=workspace/slides/[ファイル名].md`   |
| 3 / PPTX   | `make pptx-one FILE=workspace/slides/[ファイル名].md`  |
| 4 / HTML   | `make html-one FILE=workspace/slides/[ファイル名].md`  |
| 5 / いいえ | ビルドせず完了報告へ                                   |

### ステップ 8: 完了報告

**ビルドした場合：**

```
✅ スライドが完成しました！

生成されたファイル：
- PDF: workspace/output/pdf/[ファイル名].pdf
- PowerPoint: workspace/output/pptx/[ファイル名].pptx
- HTML: workspace/output/html/[ファイル名].html

確認するには：
open workspace/output/pdf/[ファイル名].pdf
```

**ビルドしなかった場合：**

```
✅ スライドの編集が完了しました！

スライドファイル: workspace/slides/[ファイル名].md

後でビルドする場合は以下のコマンドを実行してください：
make build-one FILE=workspace/slides/[ファイル名].md
```

## 追加リクエストへの対応

### 「修正して」「変更して」

1. 対象ファイルを確認（不明なら質問）
2. 修正内容を確認（不明なら質問）
3. `workspace/slides/[ファイル名].md` を編集
4. 「他に修正箇所はありますか？」と確認
5. 修正完了後「ビルドしますか？」と確認
6. ビルドする場合は形式を確認して実行

### 「画像を追加して」

1. 画像ソースを確認（URL or ユーザー提供ファイル）
2. `workspace/img/` にダウンロード/コピー
3. 「この画像でいいですか？」と確認
4. Markdown に画像を挿入：
   ```markdown
   <!-- 出典: https://example.com/page -->

   ![説明文](../img/画像名.png)
   ```
5. 「ビルドしますか？」と確認（自動ビルドしない）

**禁止事項：**

- AI 画像生成（DALL-E 等）は使用しない
- ストック画像の自動取得（Unsplash 等）は行わない
- ユーザーの指示なしに画像を追加しない

**許可される図形生成：**

- 基本図形（四角、三角、丸など）
- フローチャート（Mermaid → PNG 変換が必要）
- ダイアグラム（Mermaid → PNG 変換が必要）

**Mermaid 図の使い方：**

1. `workspace/img/diagram.mmd` に Mermaid 記法で図を作成
2. `make mermaid FILE=workspace/img/diagram.mmd` で PNG に変換
3. スライドに `![](../img/diagram.png)` で挿入

詳細: [Mermaid ガイド](mermaid.md)

### 「テーマを変えて」

1. `workspace/slides/[ファイル名].md` の Front Matter を編集
2. `theme:` の値を変更（default / gradient / darkmode）
3. 「ビルドしますか？」と確認（自動ビルドしない）

## エラー時の対応

### make new が失敗

```
❌ スライド作成でエラーが発生しました。

セットアップが完了していない可能性があります。
「セットアップして」と言ってください。
```

### make build が失敗

```
❌ ビルドでエラーが発生しました。

エラー内容：
[エラーメッセージ]

考えられる原因：
1. Front Matterの形式が正しくない（`---` で囲まれているか）
2. 画像パスが間違っている
3. Markdown構文エラー

修正が必要な箇所を特定しますか？
```

## 注意事項

- **必ず質問する**: ファイル名、テーマ、内容は推測せず必ず質問
- **make コマンドのみ使用**: npm 等の直接コマンドは使わない
- **スライドファイルのみ編集**: `workspace/slides/` と `workspace/img/` 以外は編集しない
- **システムファイル保護**: system/themes/, system/scripts/, Makefile 等は絶対に変更しない
- **画像は確認必須**: 画像を追加する前に必ずユーザーに確認する
